The spec, in one line

Protocol 003 §5: make Recall@2 and Recall@5 the primary metrics — every judged HotpotQA query has exactly two gold documents, and the prior art's closure table reports R@2/R@5 — while retaining nDCG@10 for continuity with 002, and regression-testing that 001's and 002's committed artifacts do not change.

Design decisions (spec was ambiguous → here's the call I made)

Decision Scope the measure set to the experiment instead of growing the global one. §5 said "adding R@2/R@5 to the measure set", which reads as editing rb.metrics.MEASURES. Investigating first showed that would be wrong. No measured value would move — trec_eval evaluates each measure independently — but the shape of every already-published artifact would change: make reproduce is described in the Makefile as a published promise about 001's output, and test_coordination_regression.py asserts 001's ranked dict by exact equality. So score_ranked and run_rung gained an optional measures parameter defaulting to the published set, and 003 passes GRAPH_MEASURES. Every existing caller is untouched. Confirmed empirically: the mutation that grows MEASURES globally fails 46 tests.
Decision Retain nDCG@10/R@10/R@100 rather than replace them. §5 makes R@2 primary but does not say whether the others survive. Kept, so 003's numbers sit beside 002's on the same axes and a reader can follow the sequence across entries. The cost is two extra columns; the alternative would make 003 unreadable next to 002.
Decision Name the primary and secondary measures in code, not just in prose. PRIMARY_MEASURE and SECONDARY_MEASURES are constants. §7 fixes which metric carries the registered prediction precisely so the analysis cannot promote whichever one reaches significance; leaving that only in the protocol would make it a convention rather than a constraint. A test asserts the primary is not also listed as secondary.

Deviations (intentional departures from the spec)

Deviation Protocol §5 was reworded to match the implementation. Its original text implied a global edit. Since the protocol is untagged, the honest fix is to correct it now rather than tag a document that describes something the code does not do. The reworded §5 states the scoping and the reason. Had the protocol already been tagged this would have had to be an amendment instead.

Tradeoffs (alternatives considered)

Tradeoff Optional parameter vs. a second scoring function vs. a config object. A separate score_ranked_003() would duplicate the evaluator wiring and drift. A config object is more structure than one set of strings deserves. An optional parameter defaulting to the current behaviour is the smallest change that satisfies open/closed: existing callers are not modified, and a new experiment extends rather than edits. Total production diff: 30 lines across two files.
Tradeoff Test one representative artifact, or all of them. The regression test is parametrised over every committed summary.json — 43 of them — rather than a sampled one. Shape regressions are exactly the kind of failure that hides in the artifact nobody thought to check, and the test costs milliseconds.

Open questions (want your confirm/revise)

Open Should 002's arms be re-scored with R@2/R@5 when they re-run on the pool? 003 re-runs BM25 and dense on the 66,581-passage pool (§3), and those runs are new artifacts, so they can carry the full five measures without touching anything published. I assumed yes — the paired comparison needs all arms on the same metrics. Flagging because it means 003's BM25 numbers will exist at two metric widths: three in the 002 artifacts, five in the 003 ones.
