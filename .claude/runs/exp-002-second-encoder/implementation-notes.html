Decisions

Query prefix as a constructor parameter, not a subclass. SentenceTransformerEncoder(query_prefix=...), applied only inside encode_queries via a pulled-out _with_query_prefix function. MiniLM passes None (no-op), matching its pre-amendment-2 behaviour exactly. Kept as one class rather than a per-model subclass because the only difference between the two encoders is data (name, revision, prefix, expected dim), not behaviour.
Dimension mismatch raises, doesn't auto-correct. Unlike max_length (which the code already overrides to match a request, since sequence-length truncation is configurable), embedding dimension is architectural — a mismatch means the wrong revision loaded, so _verify_dim raises rather than silently recording a number nobody asked for.
Encoder selection via one ENCODER_CONFIGS dict + --encoder CLI flag, not new rung names (dense-bge etc.) and not new run_* functions. Default "minilm" reproduces every existing call site's behaviour byte-for-byte; _dense_out_dir resolves to the existing results/002/<corpus>/dense only when encoder_key == "minilm", so nothing already committed is ever overwritten.
Used get_embedding_dimension, not get_sentence_embedding_dimension. The pinned sentence-transformers==6.0.0 renamed the method; the old one still works but raises a FutureWarning on every construction. Verified both exist in 6.0.0 before switching.

Tradeoffs

Considered a per-model subclass (BgeEncoder(SentenceTransformerEncoder)) for the prefix behaviour. Rejected: the amendment's own framing treats the prefix as a data property of a pinned revision ("this model family expects..."), and a subclass would need to override encode_queries anyway — same code, extra indirection, no test benefit (the seam constructed in tests via __new__ bypass works identically either way).
