This is a living document capturing how the implementation interprets, diverges from, or trades off against the spec. Updated as each slice lands.

The spec, in one line

Make every artifact 003 publishes regenerable by a named command, every p-value one the procedure can actually produce, the whitelist's completeness enforced where it is claimed, and both sides of the graph weighted by one rule — then recompute the registered analysis.

Deviations from the spec (the council overturned three of my own calls)

Deviation D2 — the specified floor was arithmetically wrong, so the floor was deleted rather than corrected.

The spec said floor p at 1/B. That value is impossible: the statistic is 2 · min(c_le, c_ge) / B with integer counts, so it emits only multiples of 2/B. Flooring at 1/B would report a resolution finer than the procedure has — reintroducing the exact defect being fixed, one order of magnitude down. Two council seats derived this independently; I verified it by construction.

Rather than change the constant to 2/B, I replaced the estimator with the standard add-one form 2·min(c_le+1, c_ge+1)/(B+1), which cannot return zero by construction. This removes code: the spec's max(...) clamp and its companion p_value_is_floor flag both become unnecessary. A floor plus a flag is two moving parts patching a biased estimator; this is one correct estimator.

Deviation D3 — the specified fix was self-defeating; the check moved instead of gaining a constant.

The spec proposed a hand-frozen SPACY_NER_LABELS constant asserted at import, plus a test comparing it to the real model. The council showed this fails at the invariant it exists for: an editor who breaks the partition simply edits the third constant to match, because the import-time check only compares three siblings in one file against each other. The only check against reality was a test that skips without spaCy — and this repository has no CI, so a skipped test is enforced nowhere.

Neither the spec's constant nor the council's proposed CI-gate remedy survives that. What I implemented instead is a placement change with no new state: assert_partition(labels=None) takes the inventory as an argument, and extractor._nlp() — which already loads the model and already asserts the version pin — passes the real labels. The strongest form of the invariant now runs inside every scored extraction, with nothing to drift and no skippable test.

Deviation D1 grew: the spec's verification requirement was unsatisfiable, because the file hid a fifth defect.

gate-and-seed.json publishes a graph block whose field names distinct_surface_entities and mean_entities_per_document have zero occurrences anywhere in the source tree. It was written by code that no longer exists — the same defect D1 was written to close, sitting inside the file D1 was written to fix. A literal implementation of the spec would have emitted a file missing a committed key and failed its own verification on day one.

Added graph_summary(), which reproduces the published values exactly (66,581 / 65,987 / 291,837 / 9.25). The rule I applied: had it not reproduced them, the block would have been removed from the artifact rather than quietly redefined — a number no code can regenerate does not get published.

Design decisions

Decision Holm collapses to one implementation via the adjusted-p form, not the boolean form.

holm_adjusted is the primitive; holm_correction becomes [adj <= alpha for adj in holm_adjusted(p)]. The running maximum does by construction what the old early break did by hand. 002 is published on the boolean form, so equivalence is asserted against every committed 002 decision, not just synthetic fixtures.

holm_adjusted must return input order. 002's ladder passes deliberately-unsorted p-values and zips the result against its own labels, so sorted output would silently mislabel a published comparison. There is a test that kills that mutation.

Decision The seed dedup lives in _seed, not in node_strings.

node_strings is deliberately surface-form-level and is shared with the §8.2 diagnostic, where collapsing distinct surface forms would change what the extraction score measures. Only the seeding step wants the graph's normalised key.

Decision The Makefile target covers the controls, not the scored arms.

Following the reproduce-002-lexical precedent. reproduce is a published promise about 001 and must not silently become an hours-long job; the scored arms are gated on the pre-registration tag and are run deliberately, not from a target anyone could trigger by accident.

Tradeoffs

Tradeoff The repository now has two bootstrap p-value estimators, on purpose.

stats.paired_bootstrap keeps the naive zero-capable form. Switching it would change numbers in a published entry — 002 carries 75 p_value: 0.0 entries across 27 Holm families. That is an author's decision, not a refactor's, so I measured the consequence and left the call open: correcting them flips zero Holm decisions, so only the reported figures move.

This is uncomfortable and I have flagged it rather than hidden it: a comment at the call site names the defect, points at the corrected estimator, and records the measurement. The alternative — silently fixing it — would have rewritten a published entry's numbers without anyone deciding to.

Tradeoff Cosmetic findings deliberately excluded.

Three real but cosmetic issues stay open: _query_entities' inner import (whose stated justification is untrue — the stub replaces the function itself), load_queries parsing each line twice, and the normalise name collision between coverage.py (returns a list) and extraction_score.py (returns a str). Bundling cosmetic edits into a correctness change makes the correctness change harder to review.

Open questions for the spec author

Open Does 002 get its p-values corrected?

75 zero p-values sit in published artifacts behind the shared estimator. Zero Holm decisions change if corrected. Correcting them means regenerating 002's artifacts and noting a correction on a published entry; not correcting them leaves the repository with two estimators and 002 carrying a defect this very change calls unacceptable for 003.

Open §7 lists Holm under "how it is adjudicated", but no code path lets p_holm gate anything.

The decision rules read the CI and the margin only. The entry should either state plainly that p and p_holm are reported for transparency and adjudicate nothing, or stop implying otherwise. This is a prose decision, not a code one.

Open Two 003 artifacts are untracked.

scoring-ablation.json and oracle-entity-graph.json are not in git history and have no committed producer — the same defect class as D1. They are either committed with a producing command, or not cited by the entry.
