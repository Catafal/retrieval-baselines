Bridge-entity coverage class

Branch exp-003-protocol · started 2026-08-20 · Experiment 003's query-class instrument, the piece the protocol calls the single largest threat to the entry.

This is a living document capturing how the implementation interprets, diverges from, or trades off against the spec. Updated as each slice lands.

The spec, in one line

Protocol 003 §4: for each query, count how many of its gold-document titles appear in the query text as a contiguous, case- and punctuation-normalised token sequence, under two definitions registered before any run — PRIMARY strips one trailing Wikipedia disambiguator, SENSITIVITY does not — and reproduce the frozen distributions exactly.

Design decisions (spec was ambiguous → here's the call I made)

Decision Use the scorer's tokenizer, after checking it does not move the frozen counts. 002's convention is that query properties are computed with lexical._tokenize, so a class describes the vocabulary the arms actually saw. But the frozen counts (1,821 / 3,634 / 1,950) were measured with a throwaway probe using its own regex, and adopting a different tokenizer could silently invalidate the registered numbers. Checked before choosing: both lowercase and split on non-alphanumerics (TOKEN_RE = [^a-z0-9]+), they produce identical output on 4,000 queries, and both reproduce the frozen distribution exactly. So the convention is followed at zero cost. Had they differed, the frozen counts would have won and the deviation would be recorded here instead — the registered number is the thing that cannot move.
Decision Strip only a trailing parenthetical, anchored to end-of-string. §4 says "strip one trailing parenthetical" without defining the pattern. Anchoring matters: Alpha (beta) Gamma has brackets mid-name that are part of the entity, and an unanchored pattern would rewrite it. Mutation testing confirms removing the anchor breaks three tests.
Decision A nested trailing group is left unchanged rather than partly stripped. [^)]* cannot span an inner ), so Nested (a (b) c) simply fails to match and survives whole. This surfaced as a failing test whose expectation was wrong, not the code. Leaving it whole is the safe direction: half-stripping would invent an entity name that never existed, whereas a title we failed to strip merely behaves like the sensitivity definition, which is registered and reported anyway.
Decision Make the frozen distribution a halting control, not a comment. Added controls.coverage_distribution alongside the existing pool_construction. The class is the experiment's instrument; its distribution is a fact frozen before tagging, so the code should be able to falsify the prose. The control also checks the 1,138-query disagreement between definitions — if the two suddenly agree, the normalisation changed under us and 15.4% of queries moved silently.

Deviations (intentional departures from the spec/convention)

Deviation Added a module logger; the repo has none. The skill directs "proper logging to easily debug it". No other module in this repository logs, so this is a departure from house style. Kept deliberately small and outside the hot path: one INFO line per batch classification and one for the disagreement count, nothing per-query. Logging inside title_in_query would fire ~15,000 times per run and produce noise rather than traceability. If house style should win, deleting three lines removes it.
Deviation The class lives in its own module, not in 002's query_properties. That module states it holds "the four pre-registered properties — and only these four", and 002's analysis hardcodes that tuple. Adding a fifth would require a 002 amendment and risks moving published numbers. 003 registers its property in its own protocol and its own file.

Tradeoffs (alternatives considered)

Tradeoff Contiguous token run vs. bag-of-words vs. fuzzy matching. Bag-of-words was rejected: "Chris" and "Evans" scattered through a long question is not the entity being named, and against a 20-word query almost any two-word title would match, inflating coverage-2 and destroying the negative control. Fuzzy or partial matching was rejected for a different reason — it introduces a threshold, and a threshold is a judgement call that would have to be frozen and defended, which is exactly what §4 exists to avoid. Contiguous exact match is the only rule with no free parameter.
Tradeoff Reuse 002's binning, or bin here? Coverage is already discrete (0/1/2), so it needs the existing discrete-binning path rather than quantile bins. distribution() deliberately emits all three bins even when empty, so a vanished class shows up as a zero rather than an absent key a caller might not notice — which matters because 2Wiki genuinely has no coverage-0 class, and that absence is a finding, not a glitch.

Open questions (want your confirm/revise)

Open Should the logger stay? It is the one thing here that departs from repo style. Ran with it because the skill asked for it and it is genuinely useful when a distribution control fails. Removing it is a three-line change and touches nothing else.
Open Two comparison questions sit at coverage 1. Real, in the data (comparison|1: 2). They are counted as disagreements with the gold type label, which is correct under the protocol's mapping. Flagging because they are the kind of tiny cell that later gets mistaken for a bug — they are not.

Both first-pass survivors were symmetric fixtures: a cross-tab with no comparison-question at coverage 1, and a two-query disagreement fixture returning 1 whether the code counted matches or mismatches. Both were fixed by making the fixture asymmetric. This is the same defect class 002 found in its own encoder-transposition test — a stub that could tie, so a swap was invisible — and it is why the mutation pass is run rather than assumed.

A third, quieter finding: the first mutation sweep was invalid. Stale __pycache__ left by the harness made one test report a wrong value after restore, which briefly looked like a code bug. The sweep was re-run with bytecode cleared between every mutation. A mutation harness that does not clear caches can report a mutant as killed when it was never applied.
