Experiment 004 — LLM extractor

A living document. Updated as each slice lands.

The spec, in one line

Swap 003's spaCy extractor for a pinned LLM on both corpora, changing nothing else, and report whether the graph result moves.

Design decisions

Decision GLM-4.7-Flash pinned to DeepInfra at bf16, chosen for reproducibility rather than capability. OpenRouter serves one model id from many backends at different precisions: deepseek-v4-flash spans 17 from fp4 to fp8, kimi-k2.5 spans 10 including int4, and each lab's own endpoint is often the quantised one — Z.AI serves GLM-4.7 at fp4, Moonshot serves K2.5 at int4. bf16 is the only tier where the weights served are the weights named.

003's oracle is what makes that trade correct rather than merely cheap: a perfect extractor gives R@2 0.3344 against BM25's 0.5490, so capability only matters up to a known ceiling and no model can buy past it. A reader objecting that a larger model might differ is answered by the oracle row, not by a bigger bill.

Decision The cache, not the API, is the artifact of record. An LLM is not deterministic even at temperature 0 with a seed, so make reproduce cannot mean re-calling a paid endpoint. Keys include the passage, model, provider, quantisation, prompt hash and reasoning setting, so editing any of them misses rather than silently reusing. offline=True raises on a miss, so a scored number can never come from an uncached call.

Deviations

Deviation Entities, not OpenIE triples — against NB-20's own wording. NB-20's roadmap row says "LLM OpenIE". Triples would change the graph's node and edge semantics, so the arm would differ from 003 in the extractor and the structure built on it, and no result could be attributed to either. That is 002's "the only variable is the encoder" error, where three things differed. Entity extraction on the identical (surface_form, label) contract keeps builder, linking, walk, classes, analysis and controls byte-identical. Registered in protocol §5 rather than done quietly.
Deviation The pilot gate was unrunnable as drafted, and was fixed before tagging. §8 first said "200 passages, sampled with seed 20260820". Extraction quality can only be scored where gold exists, and gold is exactly the 100 hand-annotated passages committed in 003. A fresh 200 would have had nothing to score against. Reusing the annotated set is also the stronger comparison — same passages, same rule card. The bar was fixed as a number, F1 > 0.7203, before the pilot ran, so "close enough" was not available afterwards.

Tradeoffs

Tradeoff 12 workers against provider throttling. Serial extraction at the pilot's measured 12.6s per batch is about 38 hours. 12 concurrent workers bring it to roughly 7. Concurrency is a throughput decision and not an experimental one: every call is independent and the cache is keyed by content, so what a passage returns does not depend on what else is in flight — asserted by a test that gives each passage a unique marker and checks it comes back attached to its own document. Observed throttling is 6 retries in the first 800 passages, absorbed by exponential backoff.

Open questions

Open The cost estimate was wrong by 2.6× and the entry should say so. Projected $3.70, measured $9.53. The input side was accurate; output was underestimated 3× — 60 tokens per passage assumed against 197 measured, because the model returns about 10.9 entities per passage where spaCy returned fewer. That is the same behaviour that produced the higher recall, so the overrun and the quality gain have one cause. Worth a line in the entry's cost section rather than quietly reporting the final figure.
Open The retry log does not record HTTP status codes. Retries are logged as transient failure (HTTPError) with no code, so the entry cannot report what fraction of calls were rate-limited versus failed for another reason. Not worth restarting a 7-hour run to fix; worth fixing before any future paid run.

Build / verification

  • 420 tests pass.
  • Four guards mutation-verified in isolation: the pin is sent with allow_fallbacks:false; offline mode raises on a cache miss; per-passage results are keyed by returned index so a dropped passage yields nothing rather than shifting its neighbour's entities; and the threaded fan-out keeps every passage with its own entities.
  • Two defects found and fixed while writing tests, both mine: default-argument binding meant CACHE could not be redirected, so two tests wrote fake entities into the real cache; and cache isolation is now autouse rather than opt-in.
  • Pilot passed the gate: F1 0.8565 against spaCy's 0.6703, +0.1862 on a +0.05 bar. Precision 0.6836 → 0.9092.
