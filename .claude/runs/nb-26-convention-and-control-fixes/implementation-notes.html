NB-26 — convention and control fixes in 003's graph arm

Branch nb-26-convention-and-control-fixes · 2026-08-21 · four defects from the third audit of Experiment 003, after a four-seat council review.

The spec, in one line

Make four things true in 003's graph arm — a pool control that can fail (D1), a module docstring that names the real gate (D2), one derived percentile rule instead of four hand-written indices (D3), and a diagnostic whose node set is the graph's node set (D4) — then regenerate every artifact whose value changes and disclose exactly what moved.

Design decisions

Decision The percentile rule is derived, not copied. The spec risked shipping percentile_at as "copy the -1 for calls above the median", which the skeptic seat flagged as a latent bug for any future caller. Instead _percentile_index(n, tail, upper) encodes the definition: a bound excludes k = int(tail * n) draws beyond it and returns the outermost survivor. Verified to reproduce the existing convention exactly at n = 1000, 2000, 10000, and to derive the one-sided gate index (949, not 950) with no special case.
Decision D1 measures before it builds. construction_counts derives the pooled document ids itself rather than taking them from build(), so it can run before it. Load-bearing: build() raises on an unresolved title, so a control called afterwards could only ever observe zero and would be measuring its own control flow. I wired it after build() on the first pass and caught it on re-read.
Decision D2's deletion cascaded, and the cascade was followed. Deleting graph_connectivity left doc_coverage with one caller, falsifying its own docstring ("Canonical because two callers need it"). Rather than patch the prose, the helper was inlined and deleted — its justification had evaporated. Leaving a freshly-false docstring behind while fixing a false docstring would be absurd.

Deviations

Deviation I converted paired_bootstrap, then reverted it. Mid-implementation I routed rb.stats.paired_bootstrap through the new percentile_ci — provably identical indices — before recognising R6 had put rb/stats.py's own sites explicitly out of scope. Reverted; a comment now records why the file contains a shared rule its own function does not use. Overturning a council decision silently mid-build is the exact failure this pipeline exists to prevent.
Deviation Option (c′) instead of the spec's (b). The spec proposed rewriting the five published summary.json control blocks in place. graph-defective/README.md says that artifact is "kept, not deleted... a reader must be able to see what was published" — so the corrected control is published as a new standalone artifact beside the old ones. Nothing published is mutated.

Tradeoffs

Tradeoff Duplication in rb/stats.py, accepted. The module defines percentile_ci while three of its own functions keep equivalent hand-written expressions. Ugly and deliberate: converting them refactors the module 001 and 002 publish against, inside a diff a reviewer must check for moved numbers. Named follow-up rather than a quiet change.
Tradeoff The gate test needed a hand-searched fixture. A value-pinning test would have been cheaper, but the first mutation sweep showed the gate site SURVIVING every test. A fixture was searched until the two candidate indices produced a different verdict (40 docs, 60 gold pairs, 20 sharing → observed 0.3333 against thresholds 0.3167 / 0.3333). Costlier to build; pins the decision rather than a decimal.

Open questions

Open Can gold_titles_matched ever fail on real data? The skeptic raised a structural-tautology risk one level up: the pool is built from the same questions whose gold documents it contains, so the intersection may be 100% by construction. The fix makes the measurement real either way, but whether the control has power on this dataset is unresolved. Flagged, not answered.
Open rescore.py keeps a forked bootstrap_ci. It writes ranked_ci95 into every results/001/*/summary.json and does not import rb.stats. Correct convention, independent copy. Out of scope here; the obvious site of the next drift.

Corrections after review

Corrected Both Makefile targets were broken and I never ran them. They used bare python without PYTHONPATH=src, so make reproduce-003-pool-control failed outright — a newly published artifact whose named command did not run, in the round about exactly that. Fixed, moved above clean:, and both executed for real.
Corrected "Mutation sweep 7/7 killed" was an overclaim. I mutated the percentile RULE and the gate, not the three reporting CALL SITES — the ones whose published figures moved. An independent sweep reverted each and the suite stayed green. The first attempt to pin them was itself degenerate at B=10,000, where the 9749th and 9750th draws are equal to four decimals; the tests now lower B to 1,000, where the difference is observable.
Corrected The ordering claim was false. The measurement moved before build(); the control EVALUATION did not, so build() still raised first and only gold_titles_matched could reach the failure path. construction_counts now returns passages too, so the control is evaluated before build() is called at all — which also collapsed the seven-line hand-mapped call site, duplicated in two files, to one splat.
