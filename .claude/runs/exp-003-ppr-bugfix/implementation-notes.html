PPR bug fix

Branch main · 2026-08-21 · correcting a walk that was not a walk, and re-running Experiment 003's graph arm.

The spec, in one line

Correct personalized_pagerank, which applied an unnormalised co-occurrence matrix rather than a row-stochastic transition, and re-run the arm. Classified a bug fix by Sir, since §2 registers "following HippoRAG's shape", HippoRAG's shape is PPR, and the code claimed PPR in its own docstring.

Design decisions

Decision Fix only the walk. Leave document scoring alone. Scoring sums a document's entity mass unnormalised, carrying a measured bias toward entity-rich documents. It is tempting to fix in the same pass. I did not: summing is what HippoRAG does, so changing it after seeing results would be a method change wearing a bug fix's clothes. A bug fix is "the code did not do what was registered"; this would have been "the registered method has a weakness". Only the first is legitimate post-tag.
Decision Write amendment 3 before the corrected numbers existed. Committed while the re-run was still going, stating explicitly that the arm might still lose and the differential might not survive. Framing written after the outcome cannot be trusted not to fit it.
Decision Keep the defective artifacts. Moved to results/003/pool/graph-defective/ with a README, not deleted. A reader must see what was published, what replaced it, and by how much it moved. Silent retraction would be a worse fault than the bug.

Deviations

Deviation Iterations raised 20 → 50. Not a tuning choice: a correctly normalised walk converges more slowly than the globally-rescaled version appeared to, because the rescale masked non-convergence. tol still exits early, so the higher ceiling costs nothing when it is not needed.

Tradeoffs

Tradeoff networkx as a test-only dependency. A new dependency for one comparison. Worth it: the absence of exactly this comparison is what let a non-PageRank pass every test. Every previous test checked a property the broken walk also satisfied. The dependency buys an independent implementation, which is the only thing that could have caught it.

Open questions

Open The scoring bias got WORSE, and it is now the dominant defect. Top-1 results averaged 1.45x the corpus entity count before the fix and 1.68x after — because a correctly normalised walk spreads mass more evenly, so summing rewards entity count more. Gold documents sit at 0.90x. This is very likely what holds Recall@2 down.

Deciding whether to address it is yours, and it is not obviously a bug: HippoRAG sums too. But HippoRAG's edges are OpenIE triples, so their graph has no comparable hub structure — the interaction between co-occurrence edges and summed scoring may be a genuine finding rather than a fault.

Build / verification

  • Corrected walk agrees with networkx.pagerank to 2e-6; the previous one put 2.5x less mass on the informative rare edge.
  • 300 tests pass. Three new: reference agreement, hub-discounting, dangling mass.
  • Re-run: 894s (514s build, 285,013 nodes).
  • Also fixed a test of mine scoped too broadly — the measure-shape regression globbed every summary.json including 003's, which correctly carry five measures.

The bug was real and it was not the explanation. Deep recall improved 28% relative at R@100 — the walk genuinely was broken. But Recall@2, the registered primary, did not move. The failure at the top of the ranking lives somewhere else, and the entity-count evidence points at summed scoring.

The registered claim survived and strengthened. Clause A's differential went from +0.0534 to +0.0710 on the primary metric, supported in all six cells, Holm-corrected. A conclusion that survives correcting a genuine defect in the arm it depends on is better evidenced than one that was never tested that way.
