Experiment 006 — does a precomputed graph walk move the hops out of the model

Branch exp-006-graph-answering · started 2026-08-28 · the last entry in the grep / vector / graph notebook sequence.

A living document. Updated as each slice lands.

The spec, in one line

Replicate graph-memory-starter's comparison — a model driving its own grep search, versus a precomputed knowledge-graph walk, versus BM25 — at a real sample size with real baselines, using the Claude Code subscription as the model under test, on a small corpus, across haiku / sonnet / opus.

Design decisions (spec was ambiguous → the call made)

Decision The model under test is a Claude Code agent process, not an API call. The subscription constraint forced this, and it turned out to be the more faithful design: the prior art measures agents driving Grep and Read, not chat completions. Every arm is a claude -p invocation with --output-format json, so token counts, turn counts, cost and latency are measured by the CLI rather than estimated.
Decision A new graph had to be built; 001–005's could not be reused. llm_extractor.py:5-6 records that the existing pipeline emits entities on a (surface_form, label) contract and deliberately not OpenIE triples. spaCy NER plus co-occurrence has no predicates, so the starter's mechanism — a recursive walk over typed edges — is not expressible in it. graphmem.py is a faithful reimplementation of the starter's three tables, seeding rule and recursive CTE.
Decision The extractor is pinned to haiku, the weakest tier under test. Building the graph is an LLM pass over the corpus: inference-time compute moved to build time. If the builder were stronger than the answerer, the graph arm would carry a smarter model's reasoning into a weaker model's answer and report it as structure. Pinning to the weakest tier makes that impossible. It costs the graph arm its best case, deliberately.
Decision n = 100, fixed before any answering data existed. Chosen from an a-priori power table, not from a pilot, so there is no adaptive-design hole. At n=100 the primary within-tier contrast has MDE 0.153–0.177; the three-tier interaction has MDE 0.217–0.251 and is therefore registered underpowered in advance rather than being allowed to report a null it could not have distinguished from an effect.

Deviations (intentional departures)

Deviation The corpus is 990 documents, not the starter's 8. The pool is the union of the 100 sampled questions' own HotpotQA contexts, so every other question's distractors are this question's haystack. Validity check: BM25 scores R@2 = 0.550 here against 0.549 on 003's 66,581-passage pool, and dense 0.742 against 0.696. The corpus is three orders of magnitude smaller and only very slightly easier.
Deviation The entity/predicate vocabulary is re-drawn for the domain. The starter's vocabulary (PERSON, ROLE, POLICY, PROCESS, DOCUMENT) describes a company's approval chain. HotpotQA is encyclopaedic. The shape — a closed type set and a closed predicate set, which is what makes edges walkable rather than free text — is kept.
Deviation An oracle arm was added that the original comparison has no equivalent of. The first-principles council seat argued the mechanism claim is unfalsifiable without it: a graph win over grep is indistinguishable from "the context was shorter and cleaner" unless an arm supplies the same information without the graph's structure. It is also the strawman guard — if grep on opus cannot approach oracle on opus, the control is broken.

Tradeoffs (alternatives considered)

Tradeoff More questions vs. repeated sampling per cell. The models are sampled, not greedy, so one run per cell confounds arm effect with sampling noise. Repeated runs with majority vote only sharpen questions whose success probability sits near 0.5, and majority-vote error falls roughly as sqrt(k) while MDE falls as 1/sqrt(n). Budget went to n, not k.
Tradeoff Token budget equalised at 400 tokens for every injected arm. Unconstrained top-k would let a passage arm receive 3,000 tokens against the graph's 400, and the difference in context volume would be reported as a difference in context structure. Cost: the passage arms get ~3 passages, below their best case.

Bugs found and fixed (each would have invalidated the run)

Fixed The global ~/.claude/CLAUDE.md leaked into every call. Claude Code loads user-level settings regardless of working directory, so a fresh empty temp dir does not stop it. Probed directly: the model quoted the file back verbatim. Closed with --setting-sources ""; re-probed, the model now replies NONE. The first contamination probe was measured under the leak and was discarded.
Fixed --add-dir grants corpus access but does not confine the agent to it. A grep agent given the corpus directory successfully read a canary file outside it — which would have let the grep arm reach the repository holding the gold answers. Closed with --restricted; re-probed, the read is refused with a permission denial and corpus access still works.
Fixed Call.tool_calls was declared and never assigned. It silently stayed 0 for every arm — and "0 tool calls vs 6" is the prior art's headline metric. Removed in favour of num_turns, which the CLI actually reports.
Fixed Exit code 1 was treated as failure, discarding valid results. On --max-turns exhaustion the CLI exits non-zero with empty stderr and a complete JSON result on stdout carrying usage, cost and turn count. The original code returned early and threw all of it away. stdout is now parsed first.
Fixed Three different failures were one empty answer scored as wrong. A model that ran out of turns, a process the harness killed, and an API error are now typed separately. Only the first is a fact about the model: it scores wrong and is reported separately. The other two are retried once, then excluded from the denominator — scoring infrastructure flakiness as a wrong answer would penalise the arm that takes longest, which is the grep arm, which is the control.

Open questions

Answered No — the walk is real. Registered as F6 before tagging and computed with no model calls: answer presence is 0.11 from the seed neighbourhood alone, 0.39 under the shipped walk, and 0.18 over an edge-permuted placebo graph with identical nodes and degrees. The walk contributes +0.28 over string matching and +0.21 over a random graph. graph-facts is a real retrieval mechanism. It is simply a worse one than every alternative tested.
Open The walk barely walks, and that bounds the claim. The realised depth histogram at the registered configuration is {0: 663, 1: 71, 2: 9} — 10.8% of injected facts lie beyond the seed neighbourhood and 1.2% beyond one hop. So what was falsified is the prior art's mechanism as configured: hops=3, top_k=8 with a flat cut. A depth-reserved variant was written and measured (55% at depth ≥ 1) and deliberately NOT registered, because improving the mechanism is a different experiment from testing it.
Fixed The grep arm was searching an empty directory. Caught by a pre-tag smoke test: grep scored 0 of 3 where oracle scored 2 of 3, with zero permission denials and the turn cap never reached. Every call runs in a fresh temp directory so no repo content leaks in; the corpus arrives via --add-dir; and nothing told the agent that path. Its Grep searched the empty cwd and correctly gave up. With the path supplied, the same three questions score 2 of 3 — exactly oracle's score. Had this shipped, every graph win in the table would have been an artifact of my own harness.
Fixed resolved_model recorded only the first modelUsage key. Claude Code makes a small auxiliary haiku call alongside the requested model, so 1,793 of 1,800 calls recorded "haiku" whatever tier was asked for — which reads exactly like an experiment that silently ran one model three times. It did not. Verified directly under the run's own flags, and independently from the run's cost profile: opus costs 3.6× haiku per call, sonnet 2.0×, with haiku emitting 602 output tokens per call against opus's 274. Evidence in results/006/model-resolution-check.json.

The result

The graph lost, decisively, and the author expected it to win. EM by arm:

P1 is falsified in the opposite direction (−0.27 on haiku, Holm p = 0.0006). The interaction inverts and is significant (−0.20, CI [−0.32, −0.08]): the graph hurts the weak model more, which is the exact reverse of the prior art's thesis. F4 does not fire, and that is what makes the loss credible — grep at 0.54 sits within noise of the 0.57 oracle ceiling on haiku, and beats the oracle outright on opus.

What the verification council changed

Verified The numbers reproduce from raw data. The integrity seat wrote its own SQuAD scorer rather than importing mine and recomputed all 18 arm×tier cells from calls.jsonl: every cell matches exactly. It re-derived the primary contrast independently (−0.27, CI [−0.37, −0.17], d = 0.35) and the interaction (−0.20, CI [−0.32, −0.08]). It confirmed the only src/ change after the tag was the provenance field, which nothing reads — arm and tier grouping use the --model flag recorded verbatim in each call's cmd. n = 100 in every cell, no duplicates, no missing triples, no retries, and the 5 max-turns exhaustions scored as wrong rather than dropped, which runs against the arm the record favours.
Changed The headline was measuring coverage and calling it reasoning. The adversarial seat found the one piece of arithmetic the protocol's own logic demands and that F6 never ran: answer-presence for the comparison arms, not just the graph. Ceilings are graph 0.38, BM25 0.55, dense 0.80, oracle 0.98. Dividing EM by each arm's own ceiling on haiku gives graph 0.711, BM25 0.727, dense 0.637, oracle 0.582 — the graph converts the evidence it delivered about as well as BM25 and better than dense. The loss is what the haiku extractor retained, not how the answerer used it. That is now stated beside the headline instead of buried in the limits, and it narrows the claim considerably.
Honest limit What 006 does not license. Nothing about graphs built by a strong or human extractor; nothing about genuinely deep chains, since only 1.2% of injected facts reached depth ≥ 2; nothing about small curated typed-relation corpora like the prior art's; and nothing about the personal agent-memory setting, which §1 excluded before any data existed. What it falsifies is one specific instantiation — cheaply extracted, shallowly walked, on an encyclopedic corpus where a titled-file grep baseline already sits at the oracle ceiling.
