The spec, in one line

Introduce one Retriever interface, refit 001's coordination matcher behind it without changing its numbers, add a lexical BM25 scorer with three independent switches (full factorial, Shapley attribution), a dense rung and an RRF hybrid rung, the statistics to compare rungs honestly (paired bootstrap + Holm), two new controls, a repo restructure that keeps make reproduce meaning exactly 001, and the 002 pre-registration — all without running the experiment or embedding a corpus.

Design decisions (spec was ambiguous → here's the call I made)

Decision Lexical ablation formula when saturation is off but length-norm is on. The spec names three independent switches but only gives the full BM25 formula (all three on) and says the all-off corner is "raw term-frequency sum". It does not say what the tf-component looks like when saturation is off and length-norm is on alone. I defined norm = 1 - b + b·(len/avgdl) when length-norm is on, else 1; then tf_component = tf/norm when saturation is off, and the standard tf·(k1+1)/(tf + k1·norm) when saturation is on. This reduces cleanly to raw tf when both switches are off, and to full BM25 when both are on — the two corners the spec pins down — and treats length-norm as "divide the raw count by the same length penalty BM25 would use" in between, which is the most natural reading of "one scoring function, three switches." Flagging for review since it is a real modelling choice, not just plumbing.
Decision Score encoding for every new rung matches 001's convention. 001's rank() emits len(ranked) - position rather than the raw match score, because raw scores tie and trec_eval breaks ties by its own rule instead of the pre-registered document-id rule (see rescore.py's docstring). Lexical, dense and hybrid all reuse that same strictly-decreasing rank-position encoding, so every rung's ties resolve deterministically by document id and the Retriever contract test ("strictly decreasing scores") holds for all of them uniformly.

Deviations (intentional departures from the spec/convention)

Deviation Generic runner drops 001's "set" metric family. 001's summary reports both ranked metrics and "set" metrics (recall over grep's entire unranked output, output size) because grep hands back an unordered pile and the pile's size is itself a cost. That concept is specific to a retriever that returns an unbounded set before ranking; BM25/dense/hybrid all return a bounded top-k directly, so there is no analogous "full set" to measure. The shared run_rung() only writes ranked metrics + cost + environment. 001's own run.py is untouched and keeps writing its set metrics exactly as before.

Tradeoffs (alternatives considered)

Tradeoff Encoder as an injected Protocol vs. hard-coding sentence-transformers. Hard-coding a specific model call inside DenseRetriever.retrieve() would make the ranking logic (rank/cosine/tie-break) untestable without downloading a model and installing torch. Instead DenseRetriever takes an Encoder object (name, revision, precision, pooling, max_length + encode_documents/encode_queries) and a real SentenceTransformerEncoder implements it with a lazy import so importing the module — and running the test suite — never requires sentence-transformers/torch to be installed. Chosen because the task explicitly says "write the code and its tests; do not run it on a real corpus," and this is the only way to satisfy that without a heavy, untested dependency in the critical path.

Open questions (want your confirm/revise)

Open Closure-control tolerance value. 001's external-anchor tolerance (0.10 absolute) is deliberately loose because it compares this repo's tokenisation against Anserini's. The closure control compares this repo's own lexical all-on corner against this repo's own bm25s-based anchor (already run in 001) — both are "us", so I set a tighter default of 0.02 absolute in controls.bm25_closure() and documented it in protocols/002-ladder.md. This number has not been checked against a real measured pair (no run happened), so it may need loosening once the actual all-on-corner number exists.
Open Embedding-shuffle chance ceiling. controls.embedding_shuffle() defaults to a 0.15 nDCG@10 ceiling as "chance." This is a guess at what a shuffled dense run looks like on SciFact/Quora-scale corpora and is untested against real embeddings (none were run). It is exercised in tests/test_dense.py against a small synthetic corpus where alignment is exact, which proves the mechanism (shuffle collapses the metric) but not the specific threshold.
